# Suly — رفيقك نحو الالتزام

تطبيق Android عربي لمتابعة الصلاة والورد القرآني والأذكار والتسبيح، بتصميم هادئ أخضر وذهبي، وتنقل RTL من خمس خانات بترتيب الصفين الذي حدده المستخدم.

## الوظائف والبيانات

تُحسب مواقيت الصلاة على الجهاز باستخدام مكتبة `adhan`، مع اختيار طريقة الحساب ومذهب العصر، واستخدام المنطقة الزمنية المحددة للموقع في عرض الأوقات. يمكن اختيار المدينة يدويًا أو السماح بالموقع أثناء الاستخدام. إشعارات الصلاة محلية، لكل صلاة إعداداتها، ومنها خيار الصمت والتذكير الاختياري. قد يقيّد Android وصول الإشعار أو توقيته وفق الأذونات وتوفير البطارية. تُعاد جدولة الإشعارات يوميًا وعند العودة للتطبيق؛ وفي فجوة DST لا يُرسل التنبيه في ساعة أخرى مضللة، بل يُترك لذلك اليوم.

على Android، تحفظ سجلات الصلاة والنوافل وخطة القرآن والتقدم والمفضلة والعداد والإعدادات في SQLite محلية. أما معاينة الويب فقط فتستخدم AsyncStorage بديلًا كي تعمل دون مكوّن SQLite الأصلي الخاص بـ Android. لا تُرسل السجلات أو الأهداف الشخصية إلى الخادم.

مكتبة المحتوى تبدأ محليًا وتظل قابلة للاستخدام دون اتصال. يتطلب فحص الإصدارات المنشورة وتنزيلها اتصالًا؛ يعرض التطبيق إصدارًا أحدث إن توفر، ولا يثبته إلا بعد ضغط المستخدم على «تحديث الآن». يرفض التطبيق الإصدار المتساوي أو الأقدم، ولا يستبدل المكتبة عند فشل الاتصال أو عدم وجود نشر. المزامنة للمحتوى المنشور وحده، ولا تحدّث ملفات التطبيق أو واجهته؛ تغييرات الوظائف تحتاج بناءً جديدًا.

## لوحة الإدارة — واجهة متصفح منفصلة

مسار الويب `/admin` هو لوحة الإدارة المستقلة؛ أُزيل رابطها من إعدادات APK، ويعرض مسار Android رسالة تفيد بأن الإدارة تتم من المتصفح. في بيئة المشروع افتح **Preview** لنسخة الويب ثم أضف `/admin` إلى مسار المعاينة. رابط Preview مؤقت وليس عنوان إنتاج ثابتًا؛ لم يُضبط استضافة عامة مستقلة للوحة حتى الآن.

تستخدم لوحة الويب Manus OAuth، وتتحقق إجراءات الإدارة من الدور على الخادم. تُحفظ المسودات والمصادر والمراجعة وإصدارات المحتوى في قاعدة بيانات المشروع؛ يجب مراجعة المصدر قبل نشر أي آية أو حديث. لا تتحول المسودة إلى محتوى منشور حتى ينشر المشرف إصدارًا. إعداد `OWNER_OPEN_ID` موجود في بيئة التطوير الحالية، لكن لم نتحقق بعد من أن حساب Manus الذي سيُسجّل الدخول يطابق المالك المصرح به. لا تضع المعرّف داخل APK أو في مستودع الشيفرة.

بعد نشر إصدار المحتوى، يفتحه المستخدم من **الأذكار** ويضغط **تحديث الآن** عند ظهور إصدار أحدث. تغيير واجهة التطبيق أو الوظائف، ومن ضمنها إزالة شاشة الإدارة من APK، يحتاج إعادة بناء APK؛ لا يوجد تحديث شيفرة تلقائي OTA مهيأ في المشروع.

## التطوير والفحوص

```bash
pnpm install --frozen-lockfile
pnpm db:push
pnpm dev
```

يخدم `pnpm dev` Metro للمعاينة على المنفذ 8081 وخادم API على المنفذ 3000. شُغّل `pnpm db:push` قبل أول حركة OAuth/API في نسخة بيئة جديدة، وأعده فقط عند تغيير المخطط أو الحاجة إلى مزامنة جديدة. قاعدة بيانات المشروع المدارة مشتركة بين التطوير والنشر، لذا لا تستخدمها لاختبارات إتلافية.

```bash
pnpm test
pnpm check
pnpm build
pnpm exec expo export --platform web --output-dir /tmp/suly-web-export
```

آخر تحقق في هذه النسخة: 49 اختبارًا ناجحًا واختبار واحد متجاوز من المجموعة الموجودة؛ فحص TypeScript وبناء API وتصدير Expo Web نجحت. كما أعاد Metro وAPI استجابة الحالة HTTP 200. حذّر تصدير الويب فقط من أن إشعار تغيّر push token غير مدعوم بالكامل على Web؛ إشعارات المتصفح ليست مسار المنتج الأصلي.

## بناء Android

مشروع Expo معدّ للبناء على Android ويحافظ على `applicationId` وscheme المولّدين. إصدار APK أو AAB يتم من لوحة المشروع عبر إجراء بناء Android؛ لا تُنفّذ EAS أو بناء إصدار Android داخل Sandbox. أفاد المستخدم بتنزيل APK من لوحة البناء؛ لم يتوفر فحص تثبيت فعلي لذلك الملف هنا. التغييرات الحالية على فصل لوحة الإدارة تتطلب بناء APK جديدًا كي تظهر النسخة دون رابط الإدارة داخل إعدادات Android. معاينة الويب واختبارات TypeScript لا تثبت السلوك الأصلي، لذا يلزم فحص الأذونات والتنبيهات والتخزين على Android قبل اعتبار النسخة جاهزة للإطلاق.
